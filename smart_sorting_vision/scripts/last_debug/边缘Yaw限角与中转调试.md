# 边缘Yaw限角与中转调试

本规则用于靠近电机和相机的一侧。`x > -40 mm` 时，抓取姿态只允许
**Yaw舵机实际命令角40～80°**，接触条件相近时优先靠近60°。
角度不直接套到 `PICK_TARGET yaw`；上位机先按现有Yaw标定换算，再判断。
现有通信协议和下位机Yaw换算公式保持不变。

## 配置

上位机 `config/runtime_config.yaml`：

```yaml
vision:
  top:
    edge_yaw_limit:
      enabled: true
      x_threshold_mm: -40.0
      servo_min_deg: 40.0
      servo_max_deg: 80.0
      preferred_servo_deg: 60.0
      sample_step_deg: 5.0
```

只修改自己原文件的这段，保留相机、ROI、机械映射、Yaw标定及预开口参数。
下位机中转边界在 `Control_fixed/User_File/3_Robot/edge_motion_config.h` 的
`Edge_Motion_Config::Turn_Boundary_X_mm`，与上位机阈值保持一致。

此限角只针对视觉抓取目标，已确认的固定托盘/待机角90°、110°保持原值。
这些固定姿态改为在中转边界外完成旋转后再移动到固定位置，仍需实机确认
其最终位置、高度和夹爪开口没有干涉。单条X边界不代替完整三维碰撞模型。

## 移动顺序

中转点会在 `-40` 的内侧留出XY到位容差，避免命令到 `-40`、实测停在 `-39.8`
却开始转动。按当前0.30mm到位容差，中转命令约为 `-40.31mm`，危险区判断仍用 `-40mm`。

1. 若当前实测 `x > -40`，先保持当前Yaw，退到 `(内侧中转X, 当前Y)`。
2. 实测退到边界后，再允许XY和Yaw一起运动。
3. 若目标在内侧中转X之外，第二步先到 `(内侧中转X, 目标Y)`，并等待XY到位、Yaw转动时间结束。
4. 保持已经完成的Yaw，再移到最终目标X。
5. 若目标已在内侧中转X以内，从第二步直接到目标，沿用XY和Yaw同时运动。

各段等待使用实际XY反馈；发送命令成功不代表到位。
回待机仍先抬升，夹爪在整条回程到位之后才松开。
初始已经位于边缘区时，第一段只退X，不在原地先转Yaw。

## 测试步骤

1. 更新上下位机代码，在现有已标定工程中重新编译、烧录下位机。
   保留现场已确认的机械原点、每转行程、轴方向、工作区等参数。
2. 在空托盘、低速条件下分别检查：边缘到内侧、内侧到边缘、边缘到边缘、
   边界点到内侧。确认退出边缘前Yaw保持不变，进入边缘前Yaw已经转完。
3. 核对去托盘、识别位、STOP回待机也经过中转，固定姿态与原来相同。
4. 运行顶部单物体预览：

   ```bash
   python -m scripts.last_debug.test_single_object_grasp
   ```

   将同一个物体分别放在 `x<-40` 和 `x>-40`。按 `I` 查看规划：
   `servo_deg` 是本次限制的角，`yaw_axis_deg` 是协议轴向角，两者不同。
   边缘区允许的候选仍经过宽度、预开口和接触检查；不会把原方向直接截断到边界。
5. 确认画面和机械路径后，按物理START，再按预览的Space实抓一次。
6. 取一个在限制方向下过宽的物体验证：若没有可行姿态，应继续等待/选择其它目标，
   不发送该候选，不进入永久ERROR，不把它判为空托盘。

`x=-40` 本身属于中转边界，抓取限角按严格 `x>-40` 判断。
上位机会在候选规划、共识输出和正式协议下发前复核，最后一次使用包含下降预补偿
及0.1mm/1°协议量化后的实际指令。若该步越界，只跳过候选，后续合法目标可以继续执行。

## 离线验证

视觉工程目录（需要项目现有依赖）：

```bash
python -m unittest tests.test_edge_yaw_limit tests.test_edge_yaw_pipeline tests.test_edge_yaw_runtime tests.test_edge_yaw_dispatch
```

下位机工程目录的PowerShell：

```powershell
.\tests\run_host_tests.ps1
```

离线测试验证角度换算、边界、软件时序和命令顺序；真实电机和相机的外形间隙仍以现场低速测试为准。
